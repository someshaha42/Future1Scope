AI INSTRUCTIONS: KOTLIN NATIVE ANDROID + GITHUB ACTIONS DEBUG APK
=====================================================================

GOAL
----
Inspect the existing Android project and integrate GitHub Actions so that
pushing code to the main branch automatically builds a Debug APK and uploads
it as a downloadable GitHub Actions artifact.

PROJECT REQUIREMENTS
--------------------
- Native Android application.
- Kotlin as the application programming language.
- Jetpack Compose for UI; do not introduce React, Next.js, Angular, Flutter,
  or WebView.
- ARM64 native ABI packaging only: arm64-v8a.
- Device support: Mobile and Tablet.
- Minimum Android API: 36 (Android 16).
- Maximum requested Android API: 37 (Android 17).
- Target SDK: 37.
- JVM target: 17.
- Preserve existing project names, model strings, screen names, labels, IDs,
  custom names, fragments, and click/touch interaction logic.
- Do not add unrelated application features or unnecessary dependencies.

IMPORTANT WORKING RULES
----------------------
1. Inspect the repository and identify the actual Android project root before
   editing any files.
2. Do not assume the module directory is named FrameCutUI. Use the real path
   found in the repository.
3. Preserve the Android Studio project structure and import compatibility.
4. Do not replace or rewrite unrelated source files.
5. Check the existing Android Gradle Plugin (AGP), Gradle Wrapper, Kotlin
   plugin, Compose plugin, compileSdk, and module names before changing them.
6. Keep plugin and Gradle versions mutually compatible. Do not blindly force
   AGP 9.1.1 or another version without checking compatibility.
7. If required wrapper files are missing, generate them using a compatible
   Gradle installation and commit the wrapper scripts and wrapper JAR.
8. Do not claim a successful build unless the build command actually succeeds.
9. Explain any unavoidable compatibility changes before applying them.

REQUIRED GITHUB WORKFLOW
------------------------
Create this file at the repository root:

.github/workflows/android-debug-apk.yml

Use a workflow equivalent to the following. Replace PROJECT_DIR with the
actual relative path to the Android project root. If the Android project is
already at repository root, use "." as the working directory and adjust the
APK path accordingly.

--- BEGIN WORKFLOW YAML ---

name: Android Debug APK

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read

jobs:
  build:
    name: Build Debug APK
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "17"

      - name: Set up Gradle
        uses: gradle/actions/setup-gradle@v4

      - name: Build Debug APK
        working-directory: PROJECT_DIR
        run: |
          chmod +x gradlew
          ./gradlew :app:assembleDebug --stacktrace --no-daemon

      - name: Upload Debug APK
        uses: actions/upload-artifact@v4
        with:
          name: Android-Debug-APK
          path: PROJECT_DIR/app/build/outputs/apk/debug/app-debug.apk
          if-no-files-found: error
          retention-days: 14

--- END WORKFLOW YAML ---

The AI must replace PROJECT_DIR in both locations with the actual project path.
If the app module is not named "app", use the actual module name and output
path. If the APK output filename differs, use the actual generated filename.

BUILD COMMAND
-------------
From the Android project root:

    chmod +x gradlew
    ./gradlew :app:assembleDebug --stacktrace --no-daemon

For a project inside a subdirectory, first change to that directory.

GIT COMMANDS
------------
From the repository root, after verifying the workflow and project files:

    git add .github/workflows/android-debug-apk.yml
    git add .
    git commit -m "Add GitHub Actions Android Debug APK workflow"
    git push -u origin HEAD

Do not run the commit or push commands without the user's authorization if
the AI environment does not already have explicit permission to publish.

OPTIONAL GITHUB CLI COMMANDS
----------------------------
Run a workflow manually:

    gh workflow run android-debug-apk.yml --ref "$(git branch --show-current)"

Watch the latest run:

    gh run watch

GitHub CLI must be installed and authenticated.

EXPECTED APK OUTPUT
-------------------
Typical Gradle output path:

    app/build/outputs/apk/debug/app-debug.apk

If the project is in a subdirectory, include that directory in the path.

GITHUB DOWNLOAD LOCATION
------------------------
After a successful workflow:
1. Open the GitHub repository.
2. Open the Actions tab.
3. Select the Android Debug APK workflow run.
4. Find the Artifacts section.
5. Download Android-Debug-APK.

A GitHub Actions artifact is not the same as a GitHub Release. Do not claim
that a Release is created unless a separate release-publishing workflow step
has been implemented and authorized.

FINAL VALIDATION
----------------
Before finishing:
- Confirm the workflow YAML is valid.
- Confirm the working-directory and artifact path match the real project.
- Confirm Gradle Wrapper files exist and are committed.
- Confirm the Gradle task name and application module are correct.
- Confirm JDK 17 and SDK configuration are appropriate.
- Run the Debug APK build if the environment permits.
- Report the exact build result and APK output path.
- List every file created or modified.
- Do not change unrelated UI, names, strings, fragments, or interactions.
